# Configuration

## Create a read-only service principal

azdocs authenticates as a service principal with the **Reader** role — it can
never modify anything.

```sh
az ad sp create-for-rbac --name azdocs-reader --role Reader \
    --scopes /subscriptions/<subscription-id>
```

Grant Reader on every subscription you want visible, or once on a management
group to cover them all. The command returns `tenant`, `appId`, and
`password` — the three values azdocs needs.

## Write the config

```sh
azdocs init    # interactive; chmod 600 on unix
azdocs check   # verifies token + lists visible subscriptions
```

`init` writes `azdocs.toml` to the platform config directory:

| OS | Config file | Database |
|---|---|---|
| macOS | `~/Library/Application Support/azdocs/azdocs.toml` | `~/Library/Application Support/azdocs/azdocs.db` |
| Linux | `~/.config/azdocs/azdocs.toml` | `~/.local/share/azdocs/azdocs.db` |
| Windows | `%APPDATA%\azdocs\azdocs.toml` | `%APPDATA%\azdocs\azdocs.db` |

Search order: `--config <path>` → `./azdocs.toml` → platform config dir.
`--db <path>` overrides the database location for any command.

## The config file

```toml
[auth]
tenant_id = "..."
client_id = "..."
client_secret = "..."   # optional in the file — see below

[collect]
subscriptions = []       # empty = all visible to the credential
concurrency = 4          # parallel ARG queries

[audit]
required_tags = ["environment", "owner"]   # drives missing-tag findings

[storage]
db_path = "/path/to/azdocs.db"

[branding]
company = ""                     # shown on report covers and footers
title = "Azure Estate Report"
subtitle = ""
primary_color = "#0078d4"        # brand accent used for identity and signals
accent_color = "#4da3e8"         # optional secondary for custom themes
# logo = "logo.png"              # optional; relative to this file's directory
page_size = "a4"                 # paper (Typst name, e.g. "us-letter")
margin = "2cm"                   # page margin (Typst length, e.g. "1in")
footer = "Generated by azdocs."
theme = "field-report"           # stock design; custom theme names also work
# font_dir = "fonts/"            # optional .ttf/.otf for the PDF
# font_family = "Acme Grotesk"   # overrides the theme's PDF/HTML sans
# mono_family = "Acme Mono"
```

## Branding

The `[branding]` section themes every styled report format — the HTML report
and docs site, the PDF, the DOCX and the XLSX. Every field is optional; the
defaults reproduce the stock look. Colors must be six-digit `#rrggbb` values,
and the logo may be a `.png`, `.jpg`, `.gif`, or `.svg` file.

`theme` selects a **document theme**: colours, type scale and layout
strategies, all defined in TOML rather than code. `field-report` is the only
built-in and matches the desktop design language. You can add an organisation
theme under `<config dir>/azdocs/themes/`; brand colours stay reserved for
identity, links and signals rather than document chrome. See
[reference/themes.md](../reference/themes.md).

`page_size` and `margin` apply to the PDF and the DOCX. Word only knows the
common paper sizes (A3/A4/A5, US Letter/Legal/Tabloid); anything else logs a
warning and falls back to A4 in the DOCX while the PDF still honours it.

### Fonts

The PDF sets its own type — IBM Plex Serif, Sans and Mono, vendored with the
application — so it looks the same on every machine. Point `font_dir` at a
directory of `.ttf`/`.otf` files and set `font_family`/`mono_family` to replace
the working faces.

The DOCX cannot do this: OOXML names a font and Word resolves it on the
reader's machine, and azdocs cannot embed fonts into a `.docx`. The shipped
theme therefore asks Word for Georgia, Aptos and Aptos Mono. Older Office
installs substitute their configured defaults. Override `docx_serif`,
`docx_sans` and `docx_mono` in a theme file if your organisation deploys its
own typefaces.

## Environment overrides

Recommended for the secret on shared machines and CI — env vars beat file
values:

```sh
export AZDOCS_TENANT_ID=...
export AZDOCS_CLIENT_ID=...
export AZDOCS_CLIENT_SECRET=...
```
